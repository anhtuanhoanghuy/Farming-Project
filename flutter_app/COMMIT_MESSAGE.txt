feat: Implement unified device access control with auto-logout

## Summary
Implement a centralized device access control system that automatically logs out users when:
- Device owner revokes share access (guest kicked)
- Device ownership is transferred (owner + guests kicked)
- Device is deleted (all users kicked)

All device-specific screens (Dashboard, Sensor Capacity, Sensor Config, Load Control, Diagnostics) now automatically pop and return user to home when access is lost.

## Technical Details

### Unified Mechanism
The implementation uses a single DeviceAccessWatcher service that:
1. Listens to device_shares stream (detects share revoke)
2. Listens to devices stream (detects ownership transfer)
3. On any change, calls _checkAccess() which:
   - Fetches fresh owned devices (listDevices)
   - Fetches fresh shared devices (listSharedDevices)
   - Compares against cached devices
   - Broadcasts revoked event for each lost device
   - Refreshes repository to sync state

### Why This Works for All Cases
- Share Revoke: Guest's listSharedDevices() returns empty → revoked
- Ownership Transfer (Owner): Owner's listDevices() returns empty → revoked
- Ownership Transfer (Guest): Guest's listSharedDevices() returns empty → revoked
- Device Deleted: Both owner and guests get empty lists → revoked for all

### Key Design Decisions
1. MAC Address (not UUID): Device IDs transmitted via revoked stream
   are MAC addresses because ShareRevokeListener receives MAC address
   
2. popUntil Strategy: Uses popUntil((route) => route.isFirst) to pop
   all device-specific screens regardless of nesting depth
   
3. Stream Seeding: Both shareChanges and deviceChanges seed first event
   to prevent duplicate processing
   
4. Repository Refresh: Automatically updates device list after revoke
   detection, ensuring device list screen shows changes immediately

5. Idempotent Operations: Multiple events can fire for same revoke
   (device table + share table both changed), but _checkAccess() is
   idempotent so no race conditions
